# 简介

## 项目定位

Zeka Stack 是一套企业级 Java 微服务工程体系。它的目标不只是"帮你少写几行样板代码"，而是通过统一的技术栈、分层架构和工程规范，让整个团队在构建微服务时有一个共同的起点。

与普通的 Spring Boot 脚手架相比，Zeka Stack 关注的不只是"快速起项目"，还包括：

- 构建配置如何统一
- 异常和响应格式如何规范
- 日志和链路追踪如何标准化
- 中间件如何统一接入
- 示例工程如何组织才能真正可参考

## 分层设计

Zeka Stack 采用自下而上的分层架构，每一层职责明确：

### Arco 构建基础层

构建体系的根基，提供：

- **统一父 POM**（arco-supreme / arco-builder）：管理全局依赖版本和插件版本
- **编译时增强**（arco-processor）：自动生成 Spring Boot 自动配置和 SPI 文件
- **Maven 插件体系**（arco-maven-plugin）：构建自动化、代码质量检查、脚本生成、容器化

这一层保证的是：**所有项目使用相同的构建规范，不靠口头约定。**

### Blen Kernel

基础能力内核，覆盖所有微服务都需要的通用能力：

- 统一异常处理和统一响应结构
- 参数校验扩展
- 链路追踪和日志上下文
- 认证鉴权封装
- 测试基类和工具

### Cubo Starter

围绕 Spring Boot 的 Starter 集合，解决"一个规范的 Spring Boot 应用应该长什么样"：

| Starter | 能力 |
|---------|------|
| `cubo-launcher-spring-boot` | 统一启动入口、环境装配、基础配置 |
| `cubo-rest-spring-boot` | REST API 规范：统一异常、统一响应、参数校验 |
| `cubo-mybatis-spring-boot` | 数据访问层规范：MyBatis / MyBatis-Plus 集成 |
| `cubo-logsystem-spring-boot` | 日志体系：结构化日志、动态日志级别、链路日志 |
| `cubo-openapi-spring-boot` | OpenAPI / Knife4j 文档集成 |
| `cubo-messaging-spring-boot` | 消息中间件抽象：Kafka、RocketMQ |
| `cubo-endpoint-spring-boot` | 运维端点：健康检查、指标暴露 |

### Domi Suite / Eiko Orch / Felo Space

- **Domi Suite**：基础微服务套件（认证、网关、用户管理）
- **Eiko Orch**：中间件统一封装（APM、缓存、调度、限流）
- **Felo Space**：业务示例工程（商城、支付），展示工程体系在真实业务中的落地

## 与普通 Spring Boot 脚手架的区别

| 维度 | 普通脚手架 | Zeka Stack |
|------|-----------|------------|
| 构建规范 | 靠文档约定 | arco 层硬性统一 |
| 异常/响应格式 | 各项目自定义 | blen-kernel 统一规范 |
| 日志体系 | 各项目自选 | cubo-logsystem 统一标准 |
| 中间件接入 | 逐个手动集成 | eiko-orch 统一封装 |
| 示例工程 | 通常没有或太简单 | cubo-starter-examples + felo-space |
| 代码质量 | 人工检查 | arco-maven-plugin 自动化检查 |
