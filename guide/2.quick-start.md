# 快速开始

## 简介

本篇帮助你从零开始构建并运行 Zeka Stack 的第一个示例工程。

## 前置要求

| 工具 | 最低版本 | 说明 |
|------|---------|------|
| Git | 2.13+ | 需要支持 submodule |
| JDK | 17 | 以根目录 `.tool-versions` 为准 |
| Maven | 3.8+ | 项目自带 Maven Wrapper，可不单独安装 |
| IDE | IntelliJ IDEA 推荐 | 启用 Annotation Processor |

## 第一步：获取代码

克隆主仓库及所有子模块：

```bash
git clone --recurse-submodules git@github.com:zeka-stack/zeka-stack.git
cd zeka-stack
```

如果你已经克隆了仓库但子模块为空：

```bash
git submodule update --init --recursive
```

## 第二步：构建整个框架

使用 Maven Wrapper 构建（无需本地安装 Maven）：

```bash
# 完整构建
./mvnw clean install

# 跳过测试（加速构建）
./mvnw clean install -DskipTests

# 只构建某个模块及其依赖
./mvnw clean install -pl blen-kernel -am
```

> [!注意]
> 首次构建需要下载大量依赖，请确保 Maven 仓库配置正确。如果构建较慢，先使用 `-DskipTests` 跳过测试。

## 第三步：运行示例工程

### 方式一：REST API 示例

最简单的入门示例，展示统一异常处理、统一响应格式和参数校验：

```bash
./mvnw -f cubo-starter-examples/cubo-rest-spring-boot-sample/cubo-rest-spring-boot-sample-servlet/pom.xml spring-boot:run
```

按启动日志确认实际端口和路径，再请求示例接口验证。

### 方式二：MyBatis 数据访问示例

展示 MyBatis / MyBatis-Plus 集成规范：

```bash
./mvnw -f cubo-starter-examples/cubo-mybatis-spring-boot-sample/cubo-mybatis-spring-boot-sample-single/pom.xml spring-boot:run
```

### 方式三：日志系统示例

展示结构化日志、动态日志级别调整：

```bash
./mvnw -f cubo-starter-examples/cubo-logsystem-spring-boot-sample/cubo-logsystem-spring-boot-sample-log4j2/pom.xml spring-boot:run
```

### 方式四：业务示例工程

如果你想看 Zeka Stack 在真实业务场景中的应用：

先查看 `felo-space` 中具体业务模块的 POM、配置与 README，选择可启动的叶子模块；不要在聚合目录直接运行 Spring Boot。

## 典型项目结构

业务项目按模块组织；下面展示推荐业务结构，具体示例的目录以实际源码为准：

```
cubo-rest-spring-boot-sample/
├── pom.xml
├── src/
│   ├── main/
│   │   ├── java/
│   │   │   └── dev/dong4j/zeka/stack/sample/
│   │   │       ├── SampleApplication.java      # 启动类
│   │   │       ├── controller/                  # 控制器
│   │   │       ├── service/                     # 业务逻辑
│   │   │       ├── dao/                         # BaseDao
│   │   │       └── entity/                      # po / dto / form / converter
│   │   └── resources/
│   │       └── application.yml                  # 配置文件
│   └── test/
└── README.md
```

### 关键 pom.xml 配置

```xml
<!-- 继承 Zeka Stack 的业务型父 POM -->
<parent>
    <groupId>dev.dong4j</groupId>
    <artifactId>arco-business-parent</artifactId>
    <version>3.0.0-SNAPSHOT</version>
    <relativePath/>
</parent>

<!-- 引入 REST Starter -->
<dependency>
    <groupId>dev.dong4j</groupId>
    <artifactId>cubo-rest-servlet-spring-boot-starter</artifactId>
</dependency>
```

版本由项目 BOM 管理；完整 parent/BOM 与业务代码范式见 [For Agents](../ai/index) 和 [工程规范](../ai/1.arch)。

## IDE 配置

### IntelliJ IDEA

1. 选择 **File → Open**，选择项目根目录的 `pom.xml`
2. 选择 **Open as Project**
3. 确保 JDK 与 `.tool-versions` 一致：
   - **File → Project Structure → Project → SDK**
4. 启用注解处理器：
   - **Settings → Build, Execution, Deployment → Compiler → Annotation Processors**
   - 勾选 **Enable annotation processing**

## 常见问题

### 子模块目录是空的

**现象**：克隆后子模块目录只有 `.git`，没有代码。

**解决**：

```bash
git submodule update --init --recursive
```

### 构建时找不到依赖

**现象**：Maven 报 `Could not resolve dependencies`。

**解决**：检查 `supports/maven/` 下的 Maven 仓库配置，确保 `settings.xml` 中配置了正确的仓库地址。

### 构建太慢

**解决**：

```bash
# 跳过测试
./mvnw clean install -DskipTests

# 只构建你需要的模块
./mvnw clean install -pl cubo-starter/cubo-rest-spring-boot -am
```

### Annotation Processor 不生效

**现象**：IDE 报找不到自动生成的配置类。

**解决**：确认 IDE 已启用 Annotation Processor，并重新构建项目（Build → Rebuild Project）。
