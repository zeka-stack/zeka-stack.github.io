## 前言：为什么要自定义 Maven 插件

Zeka.Stack 脚手架所开发的项目, 部署包采用 Fat Jar 的方式提供,

- 🏗️ 项目中遇到的重复构建流程或人为操作
- 🔁 构建生命周期中缺失的一环
- 🚀 插件带来的开发效率提升与工程一致性
- 🤔 写插件其实没有想象中复杂

## 🔧 Maven 插件开发基础速通

### 📦 Maven 插件的本质：Mojo 是什么？

- 🔨 每个插件由多个 Mojo（Maven plain Old Java Object）组成
- 🧬 每个 Mojo 对应一个 Java 类 + `@Mojo` 注解
- 🧷 `@Mojo(name = "…", defaultPhase = …)` 注解参数解析

### 🌀 生命周期机制和插件执行流程

- 🔄 生命周期（Lifecycle） vs 插件目标（Goal）
- 🧱 三大生命周期：clean、default、site
- ⛓️ 如何将插件绑定到特定生命周期阶段

### 🗂️ 插件的结构、依赖与构建方式

- 📁 标准目录结构及必要依赖说明
- 🧩 插件项目必须使用 `maven-plugin` 打包类型
- 📌 插件 POM 文件的最佳实践配置

### ⚙️ 注解配置与参数传递方式

- 🎛️ `@Parameter` 注解的使用及支持的数据类型
- 📡 配置值传递方式：`<configuration>`、系统属性、POM property
- 🧩 通过 `@Component` 注入 Maven 核心组件

### 🐞 插件调试技巧

- 🧪 本地 install 与 SNAPSHOT 版本调用的区别
- 🐛 使用 `mvnDebug` 进行远程调试的方法
- 🧭 插件日志配置与生命周期调试技巧

## 🛠️ 我的几个小插件与背后的动机

> 每节建议包含：场景背景 🧩 + 插件目标 🎯 + 实现方式 🛠 + 效果展示 ✨

### 📘 插件一：build-env-info

- 🧩 **背景**：构建信息缺失，难以溯源
- 🎯 **功能**：注入构建时间、Git 版本、JDK 信息到资源文件
- 🛠 **实现**：使用 BuildContext 写入 target/classes
- ✨ **效果**：构建信息自动入 jar，无需手工处理

### 🔄 插件二：swagger-openapi-sync

- 🧩 **背景**：文档平台接口频繁变更，难以保持一致
- 🎯 **功能**：构建时自动拉取 OpenAPI JSON 并生成本地接口文档
- 🛠 **实现**：结合 HTTP 下载、缓存检测和文档生成工具
- ✨ **效果**：接入平台接口文档从此一键同步

### 🧭 插件三：multi-module-check

- 🧩 **背景**：多人开发时子模块容易遗漏，构建出错
- 🎯 **功能**：检查是否有实际目录未加入聚合 POM
- 🛠 **实现**：对比 reactorProjects 与文件系统
- ✨ **效果**：CI 阶段自动检查，提升稳定性

## 🕳️ 开发插件时踩过的那些坑

- ❌ Mojo 类缺少 public 修饰或无参构造方法
- ❌ `@Parameter` 注入失败的常见原因分析
- ❌ 生命周期绑定错误导致插件不生效
- ❌ 插件依赖污染主项目依赖树
- ❌ 多模块项目中的 Mojo 执行顺序问题

---

## 🎯 总结：自定义插件，不只是造轮子

- 🧠 插件是团队工程治理的加速器
- 🧰 好的插件让构建更智能、更规范
- 🛤️ 插件设计要注意通用性与可配置性
- ❗ 插件适合做工程自动化、构建增强、文档同步等场景，不建议承载业务逻辑
