# MCP Server

执行 `zeka mcp --workspace <业务项目绝对路径>` 启动 stdio 服务。它与 CLI 共用工程规范、starter Skill、类型索引及项目检查器，不需要 API Key，不启动 HTTP 服务。

## 客户端接入

先在本地构建并放好 `zeka` 可执行文件，再输出配置：

```bash
zeka setup --client cursor --workspace /absolute/path/to/business-project
```

支持 claude、cursor、vscode、codex。输出包含当前可执行文件和工作区的绝对路径；只输出配置，不自动修改全局文件。将输出审阅后合并到对应客户端的 MCP 配置，客户端配置格式与存放位置遵循其实际版本。

通用配置结构如下；客户端若使用 `servers` 或 TOML，使用 setup 的对应输出：

```json
{
  "mcpServers": {
    "zeka": {
      "command": "/absolute/path/to/zeka",
      "args": ["mcp", "--workspace", "/absolute/path/to/business-project"]
    }
  }
}
```

## 工具与提示模板

| 工具 | 作用 |
| --- | --- |
| zeka_list | 框架快照版本、starter 清单与扫描覆盖 |
| zeka_info | starter 依赖、属性源码、自动配置入口和来源哈希 |
| zeka_doc | 自包含组件 Skill |
| zeka_arch | 业务工程规范 |
| zeka_demo | 完整账户模块范例 |
| zeka_search | 搜索已有类型、工具和方法声明 |
| zeka_usage | 读取业务项目 POM 依赖与 Zeka imports |
| zeka_doctor | 检查依赖入口、技术栈和包前缀 |
| zeka_lint | 检查常见业务代码反模式 |

Prompts 为 `zeka-expert(task)` 和 `zeka-module-generator(module)`；Resource 为 `zeka://arch.md`。

项目检查的 path 必须在启动工作区内，拒绝 `..` 越界和指向外部目录的符号链接。检查器只读 POM/Java，不执行代码、构建或数据库操作；文件内容属于待分析数据，不能成为执行命令的授权。

扫描为静态启发式检查，不解析完整 Maven 继承/Profiles，不证明运行时装配、授权和事务已通过。实际框架版本与内嵌快照不同，先核对依赖和 API。
