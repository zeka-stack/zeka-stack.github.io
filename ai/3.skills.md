# Skills

Zeka Stack 分别提供业务开发 Skill 和具体 starter 的组件 Skill。

## 业务开发 Skill

[SKILL.md](https://zekastack.dong4j.site/docs/SKILL.md) 定义开发顺序：读取项目约定 → 选择依赖 → 查询现有封装 → 实现业务分层 → 验证。内容包含核心编码规则，即使 CLI 不可用也能理解。

```bash
zeka skills extract --dir .agents/skills
```

默认只导出业务 Skill。按实际 starter 导出组件 Skill 及其本地 starter 依赖：

```bash
zeka skills extract --dir .agents/skills --starter cubo-ssm-spring-boot-starter
```

目录按实际客户端支持选择；这是相对当前业务项目的路径。CLI 默认不覆盖不同内容，先审阅差异，明确需要时加 `--force`。`--all` 仅适合维护和查阅，不建议将互斥技术栈的所有 Skill 自动加载到一个业务项目。

## 组件 Skill

15 个可依赖 starter 均维护自己的 `skills/<artifactId>/SKILL.md`。正文自包含，说明依赖、选型、编码、配置、Bean 扩展与运行条件，不依赖解包后不可见的仓库路径。

[按组件读取纯文本 Skills 索引](/skills/llms.txt)。该索引和各组件下载文件直接从源码 Skill 生成，与 CLI 使用同一来源。

SkillsJars 插件由父 POM 统一管理。发布方完成 starter 打包/发布后，业务项目依赖相应 JAR，再运行：

```bash
./mvnw com.skillsjars:maven-plugin:0.0.7:extract -Ddir=.agents/skills
```

插件只解析当前项目依赖图和插件 dependencies 中的 JAR，不扫描整个本地 Maven 仓库。源码中的新 Skill 不会自动出现在尚未重新打包的旧 JAR 中。

CLI 导出反映二进制内嵌的源码快照，SkillsJars 导出反映实际依赖版本；使用不同版本时应优先核对实际依赖，不将这两条分发路径当成自动版本同步。
