# Go CLI

`zeka` 将业务规范、starter Skills 和框架类型索引打包到单个二进制，查询时不联网。当前为仓库内首版实现，尚未发布到公共下载渠道；以下使用本地源码构建。

## 构建

在完整框架仓库根目录执行：

```bash
make ai-generate
make zeka-cli-build
./supports/zeka-cli/bin/zeka version
```

需要 Go 1.25 和 Python 3。首次 Go 构建下载依赖；生成知识需要初始化框架子仓库。之后二进制查询离线运行，可以把它放到开发者自己的 PATH 目录。

## 查询与开发

```bash
zeka list
zeka info cubo-mybatis-spring-boot-starter
zeka info cubo-mybatis-spring-boot-starter --detail
zeka doc cubo-rest-servlet-spring-boot-starter
zeka arch
zeka demo
zeka search StringUtils
zeka search DictionaryService --limit 5
zeka usage /path/to/project
zeka doctor /path/to/project
zeka lint /path/to/project --strict
```

文档默认输出 Markdown，结构化结果默认输出 JSON；`--format json` 将文档也输出为 JSON 字符串。错误输出到 stderr，退出码 1 表示命令/IO 错误，2 表示参数错误，3 表示 `--strict` 扫描存在 warning。

info 默认输出精简属性声明与来源，`--detail` 才附完整属性类和自动配置源码，减少无关内容占用 Agent 上下文。MCP 的 zeka_info 对应提供 detail 参数。

检查结果包含规则编号、严重度、文件、行号与建议。doctor 检查直接声明的依赖、聚合 POM 误用和包前缀；lint 提示字段注入、裸 BaseMapper、Controller 直连 DAO、PO 输出、虚构消息 API 等。扫描忽略构建目录和符号链接，单文件上限 8 MiB，总文件上限 20000。

## 技能导出和 MCP

```bash
zeka skills extract --dir .agents/skills --starter cubo-ssm-spring-boot-starter
zeka setup --client cursor --workspace /path/to/project
zeka mcp --workspace /path/to/project
```

默认只导出业务 Skill，指定 starter 后附带其 starter 依赖。不同内容不自动覆盖；setup 只输出配置。详见 [Skills](./3.skills) 和 [MCP](./4.mcp)。

## 维护与版本边界

```bash
make ai-check
make zeka-cli-test
```

生成脚本扫描所有初始化工程目录，为源码/文档建立哈希清单；公开类型索引附包名、声明、说明和路径。配置来源是属性类源码及自动配置入口，不以可能过期的 target 产物冒充当前事实。

本工具只内嵌当前快照，暂不提供跨历史版本的 API 切换、自动迁移或框架升级。类型索引和 lint 都不替代 Java 编译及运行测试。
